# ゼロベース思考

[English](README.md)

「これ以上、今のものに改善を重ねても違う気がする」ときや、まだ何もない構想段階で使うSkillです。対話から違和感や本当に実現したい価値を言葉にし、過去の決定やDocsも見直して、必ず一度は白紙から考えます。

白紙から考える工程は必須です。その結果は、継続、部分修正、コアを残した再構築、全面的な作り直し、別のアプローチ、検証、保留、中止のいずれにもなり得ます。

**状態: 実験版 0.1.1。** [評価方法と結果](eval/README.md)は合成事例での確認です。あらゆるモデルや実際のユーザーでの効果を実証したものではありません。

## 使い方

利用環境のSkill選択機能、または対応する環境で次のように呼び出します。

```text
$zero-base-thinking
このSkill、何か違う気がする。違和感を整理して、目的も含めてゼロベースで考えて。
```

「ゼロベースで考えて」という自然文の明示依頼も対象です。単に「煮詰まった」「改善して」「新しく作って」と言っただけでは、この対話手順を始めません。既存の成果物がない場合は、実現したい価値から始めます。

自由な検討を頼んだ場合は、AIが短く状況を受け止め、具体的な問いを出して壁打ちを始めます。「まず質問して」と追加で頼む必要はありません。仮案を先に見たい場合は、その希望を伝えてください。

問いの目的は、本人の意図が本人の言葉で表れるのを助けることです。選択を入口に、選んだ理由や具体的な場面、言い足りないことまで話せるようにします。

選択肢には、選んだ後に誰の何が変わるか、どんな負担や不確実さがあるかを添えます。選択肢をきっかけに「どれも違う」「こちらも気になる」と気づいたことも、その後の問いへ反映します。

「この質問の意味を、例を使って説明してほしい」「まだ決められない」も有効な回答です。回答期限を設けず、無回答や初期選択を同意として扱いません。説明を求められた回数や言葉は、この対話の説明を調整するために使います。技術力の点数や、永続的な人物像にはしません。

[架空の対話例](examples/skill-redesign.ja.md)で、説明の依頼から新しい論点が生まれ、白紙案の検討へ進む流れを確認できます。例と評価用の事例は合成したもので、特定の利用者のプロジェクトや個人設定を記録したものではありません。

## 導入

Skillを導入できるAIエージェントなら、次のように頼めます。

```text
https://github.com/NemuKei/zero-base-thinking にある Zero-Base Thinking を、
私が使っているAIエージェントのSkillとして導入してください。既存の導入があれば
上書き前に差分を確認し、本体と質問ガイドを読み込めることを確認してください。
```

ターミナルを使う場合は、Node.js 22.20以上を用意し、次の1行を実行します。

```sh
npx skills add NemuKei/zero-base-thinking --skill zero-base-thinking --global
```

**導入の検証範囲:** 現時点で確認済みなのは、独立したプロジェクト内へのファイル配置です。全プロジェクト共通の導入（`--global`）と、実際のAIアプリでの認識・呼び出しは、まだ通しで確認していません。[導入の検証記録](eval/README.md#installation-checks)

選択画面が出たら、使うAIエージェントを選びます。[標準のskills CLI](https://github.com/vercel-labs/skills)が配置先を扱うので、ファイルを個別にコピーする必要はありません。Codexに限定するなら末尾に`--agent codex`、Claude Codeなら`--agent claude-code`を付けます。

一つのプロジェクトだけに導入したい場合は、そのプロジェクトで実行し、`--global`を外します。ダウンロードしたフォルダーや展開済みZIPから導入する場合は、`NemuKei/zero-base-thinking`をそのフォルダーのパスに置き換えます。その中で実行する場合は`.`を指定できます。

導入対象は[`skills/zero-base-thinking/`](skills/zero-base-thinking/INSTALL.md)の5ファイルです。本体、質問ガイド、設定、ライセンス、短い導入案内を含みます。評価記録や開発者向け資料は、Skillの導入先へ入りません。

導入後はSkill選択機能で見つかることを確認します。Codexでは`$zero-base-thinking`、Claude Codeでは`/zero-base-thinking`で指定します。手動配置する場合は[短い導入案内](skills/zero-base-thinking/INSTALL.md)を参照してください。

## 発火と利用環境

付属の`agents/openai.yaml`では、明示的な自然文からの発見を可能にするため、`allow_implicit_invocation: true`としています。説明文と本文の開始条件で、ゼロベース思考を明示的に依頼された場合だけに限定します。この意味判断の仕組みは、厳密な文字列の一致を保証するものではありません。

CodexでコマンドやSkill選択機能からの呼び出しだけに制限する場合は、導入先の`policy.allow_implicit_invocation`を`false`にします。その場合、自然文の一言だけによる自動選択には頼らず、Skillを直接指定します。[OpenAI公式のSkill案内](https://learn.chatgpt.com/ja-JP/docs/build-skills)

質問UIの時間表示や初期選択は、Skillだけで消せるとは限りません。回答を急かさずに使える質問UIを選び、必要なら利用環境で許される通常の自由記述の対話へ切り替えます。

## 役割

このSkillが返すのは、違和感や機会、本当に解くべき問い、白紙から組み立てた案、選び直した方針とその結果、未確認事項と次の一手です。

Docsは過去の決定と根拠を知る資料として読み、妥当性を再検討できます。現在の利用者が明示した条件や、実際の外部契約は区別します。思考の見直しだけで、実装の削除や公開まで許可された扱いにはしません。

リポジトリ、メモリー、別エージェント、他のSkillは必須ではありません。本人が明示した説明の好みを、許可されたメモリーから参照できる場合は最初の説明に使えます。参照できない環境でも日常語から始め、対話中の反応に合わせます。

方向性が決まった後は、必要に応じて仕様整理や実装などの通常の手順へ進みます。特定の別Skillや、個人の運用設定からの移行は前提にしません。
